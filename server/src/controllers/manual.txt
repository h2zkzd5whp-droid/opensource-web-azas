[CRITICAL MANDATE: CONFLICT RESOLUTION RULES]
- 하나의 코드 라인에서 복수의 취약점이 발견될 경우, "가장 높은 감점 등급(warning)"을 가진 단 하나의 카테고리에만 할당한다. (중복 감점으로 인한 점수 폭락 방지)
- 가독성과 성능이 동시에 걸쳐있는 문제의 경우, 알고리즘 시간복잡도/메모리에 직접적 부하를 주면 [성능], 구조적 단순화 및 문맥적 해석에 그치면 [가독성]으로 분류한다.
- 유지보수성과 예외안정성이 충돌할 경우, 시스템 크래시나 런타임 에러 유발 가능성이 존재하면 [예외안정], 단순히 향후 코드 수정의 난이도 문제라면 [유지보수]로 엄격히 제한한다.

--------------------------------------------------------------------------------
SECTION 1. READABILITY (가독성 정밀 진단 매뉴얼)
--------------------------------------------------------------------------------
목적: 코드의 문맥적 직관성 확보, 휴먼 에러 유발 가능성 차단, 최신 언어 명세(Idiomatic Code) 준수 여부.

A. CRITICAL WARNING CRITERIA (심각한 가독성 결함: 건당 -15점)
   - [RD-W01] 의도를 알 수 없는 축약형 명명: 단일 문자 변수(i, j, k 루프 인덱스 제외), a1, temp, data 등 맥락을 유추할 수 없는 불투명한 식별자 사용.
   - [RD-W02] 매직 넘버/스트링의 무분별한 인라인 사용: 비즈니스 논리적 의미를 지닌 숫자나 문자열이 상수로 분리되지 않고 조건문/연산식에 직접 하드코딩된 경우.
   - [RD-W03] 안티 패턴 표현식 사용: 최신 사양(ES6+)을 무시한 전역 스코프 오염 변수 선언(var 사용 등), 구식 문자열 결합(비-템플릿 리터럴 문법 결합).
   - [RD-W04] 과도한 함수 매개변수 (Long Parameter List): 함수의 인자(Arguments)가 명확한 객체 구조화(Options Object) 없이 4개 이상 나열되어 호출 순서 왜곡 오류를 유발하는 경우.

B. MINOR INFO CRITERIA (일반 가독성 개선 권고: 건당 -5점)
   - [RD-I01] 부적절하거나 노이즈가 되는 주석: 코드를 그대로 언어 번역한 수준의 불필요한 주석, 혹은 최신화되지 않아 코드 본문과 모순되는 레거시 주석.
   - [RD-I02] 지나치게 긴 단일 라인: 한 줄의 코드가 가로로 너무 길어(일반적으로 100자 이상) 가독성을 해치는데도 줄바꿈(Formatting) 처리가 안 된 경우.
   - [RD-I03] 일관성 없는 표기법: 한 파일 내부에서 camelCase, snake_case, PascalCase가 일정한 규칙 없이 혼용된 경우.
   - [RD-I04] 이중 부정 및 복잡한 불리언 표현식: `if (!isNotReady)`와 같이 뇌내 인지 부하를 주는 이중 부정어 사용 혹은 지나치게 복잡한 인라인 불리언 연산문 (긍정문이나 서술적 변수 추출 대상).

--------------------------------------------------------------------------------
SECTION 2. PERFORMANCE EFFICIENCY (성능 효율성 정밀 진단 매뉴얼)
--------------------------------------------------------------------------------
목적: 시간/공간 복잡도 최적화, 불필요한 자원 낭비 최소화, 고부하 환경에서의 확장성 확보.

A. CRITICAL WARNING CRITERIA (심각한 성능 결함: 건당 -15점)
   - [PF-W01] 비효율적 시간 복잡도 유발 루프: O(N) 이하로 최적화 가능한 로직임에도 불구하고 2중 이상의 중첩 루프를 사용하여 O(N^2) 이상의 불필요한 비용을 발생시키는 경우.
   - [PF-W02] 루프 내부의 무거운 자원 재할당: 대규모 반복문(for, while) 내부에서 고비용 객체, 대형 배열, 함수 컨텍스트를 지속적으로 새로 생성하여 가비지 컬렉터(GC)에 심각한 부하를 주는 경우.
   - [PF-W03] 순차적 비동기 블로킹 (Async Waterfall): 독립적인 여러 비동기 I/O 작업들을 'Promise.all' 등으로 병렬 처리하지 않고, 반복문 내부에서 개별적으로 'await'를 호출하여 순차 블로킹 병목을 유발하는 경우.
   - [PF-W04] 비효율적 탐색 구조 사용: 대량의 데이터 처리 중 빈번한 포함 여부 검증(Lookup) 시, O(N) 복잡도를 가진 Array.includes / Array.find를 반복적으로 사용하는 경우 (O(1)의 Set/Map 구조 전환 대상).
   - [PF-W05] 대규모 배열 메서드 체이닝 오남용: 거대한 데이터셋에 대해 `.filter().map().filter()` 구조를 남용하여 메모리에 임시 배열을 불필요하게 대량 양산하고 순회 횟수를 늘리는 구조 (단일 loop나 .reduce로 통합 대상).
   - [PF-W06] 해제되지 않는 자원 (Resource Leak): 타이머(setInterval), 웹소켓, 이벤트 리스너, 스트림 등을 생성한 후 적절 시점에 명시적으로 해제(Clear/Close/Unsubscribe)하지 않아 메모리 누수를 유발하는 경우.

B. MINOR INFO CRITERIA (일반 성능 개선 권고: 건당 -5점)
   - [PF-I01] 불필요한 중복 연산: 루프 실행 조건식이나 내부에서 변하지 않는 상숫값을 매 루프마다 반복적으로 계산하는 구조 (정적 값의 외부 변수 추출 대상).
   - [PF-I02] 불필요한 구조적 복사: 메모리가 거대한 객체나 배열을 불필요하게 얕은/깊은 복사(Spread 연산자의 남용 등)하여 메모리 점유율을 일시적으로 폭증시키는 경우.

--------------------------------------------------------------------------------
SECTION 3. MAINTAINABILITY (유지보수성 정밀 진단 매뉴얼)
--------------------------------------------------------------------------------
목적: 단일 책임 원칙(SRP) 준수, 결합도 낮추기 및 응집도 향상, 기능 확장 시 사이드 이펙트 최소화.

A. CRITICAL WARNING CRITERIA (심각한 구조 결함: 건당 -15점)
   - [MT-W01] 거대 함수 (God Function): 단일 함수의 물리적 라인이 40줄을 초과하거나, 하나의 함수 내에서 3가지 이상의 서로 다른 도메인 비즈니스 로직을 동시 처리하는 경우.
   - [MT-W02] 깊은 제어문 중첩 (Deep Nesting): if-else, switch, loop 블록이 3단계(3 Levels) 이상 심하게 파묻혀 있어 코드 흐름 추적이 극도로 난해한 경우 (Early Exit/Guard Clause 미도입).
   - [MT-W03] 코드 복사-붙여넣기 (DRY 원칙 위배): 완전히 동일하거나 80% 이상 유사한 시퀀스를 가진 5라인 이상의 코드 블록이 추상화/모듈화되지 않고 다중 위치에 중복 기재된 경우.
   - [MT-W04] 부수 효과 유발 (State Mutation Anti-Pattern): 함수 외부의 전역 상태를 직접 수정하거나, 인자로 전달받은 객체/배열의 원본 데이터(Reference)를 직접 변경(Mutation)하여 예측 불가능한 부작용을 낳는 불순한 구조.

B. MINOR INFO CRITERIA (일반 유지보수 개선 권고: 건당 -5점)
   - [MT-I01] 강한 결합을 유발하는 설정 하드코딩: API 엔드포인트, 환경 변수, 모드 값 등이 별도 환경 파일(.env)이나 전역 설정 오브젝트로 분리되지 않고 비즈니스 컴포넌트에 깊게 박힌 경우.
   - [MT-I02] 유연하지 못한 확장 구조: 향후 분기(조건)가 늘어날 것이 자명한 비즈니스 로직임에도 다중 else-if문으로 도배되어 있는 경우 (매핑 오브젝트나 다형성 구조 전환 권고).
   - [MT-I03] 추상화 수준의 불일치: 하나의 함수 안에서 고차원 비즈니스 로직 플로우와 저차원 원시 데이터 가공(예: 문자열 파싱 규칙 변형)이 뒤섞여 기재된 경우.

--------------------------------------------------------------------------------
SECTION 4. EXCEPTION SAFETY (예외 안정성 정밀 진단 매뉴얼)
--------------------------------------------------------------------------------
목적: 런타임 크래시 방지, 방어적 프로그래밍 구현, 데이터 정무적 보안성 확보.

A. CRITICAL WARNING CRITERIA (심각한 안정성 결함: 건당 -15점)
   - [SF-W01] 예외 처리 누락: 네트워크 요청, 파일 I/O, JSON 파싱 등 외부 런타임 환경에 따라 백프로 에러가 발생할 수 있는 잠재 영역에 try-catch 또는 에러 핸들러 메커니즘을 누락한 경우.
   - [SF-W02] 무방비한 참조 (Null Pointer Dereference): 외부 API 응답 데이터나 유저 입력 객체의 뎁스 구조를 검증하지 않고 직접 프로퍼티(예: res.data.user.profile)에 접근하여 TypeError 크래시 위험을 유발하는 경우 (Optional Chaining 미사용).
   - [SF-W03] 보안 취약점 노출: 하드코딩된 Secret Key, Credential, JWT 토큰이 평문으로 유출되어 있거나 외부 인젝션 공격에 무방비한 동적 쿼리/스크립트 조립을 수행하는 경우.
   - [SF-W04] 무의미한 에러 swallow (Silent Catch): try-catch 블록을 구성했으나 catch 문 내부를 완전히 비워두거나 에러 로그조차 남기지 않아, 에러 발생 시 시스템 오작동의 추적을 원천 불가능하게 만드는 안티 패턴.
   - [SF-W05] 예외 처리가 없는 비동기 흐름 (Floating Promise): async 함수나 Promise를 호출하면서 `await`나 `.catch()` 처리를 누락하여 UnhandledPromiseRejection 예외로 프로세스를 불안정하게 만드는 경우.

B. MINOR INFO CRITERIA (일반 안정성 개선 권고: 건당 -5점)
   - [SF-I01] 암묵적 형변환 유스케이스: 엄격한 비교 연산자(===, !==) 대신 암묵적 타입 변환을 유발하는 동등 연산자(==, !=)를 오남용하여 사이드 이펙트 유발 여지가 있는 경우.
   - [SF-I02] 불완전한 방어 선언: switch문에 'default' 분기가 누락되었거나, 배열 인덱스 접근 전 배열의 유효 크기(Length)를 전혀 체크하지 않는 소극적 방어 코딩.
   - [SF-I03] 위험한 부동소수점 직접 비교: 소수점 연산 결과물(예: 0.1 + 0.2)을 허용 오차(Epsilon) 없이 `===` 연산자로 직접 비교하여 알고리즘 테스트 케이스 통과를 실패시키는 연산 구조.
